# Stage 17 — Исправления панели ввода (п.1), голосовые сообщения (п.37), индикатор прочитано/доставлено (п.27)

## 1. Исправления нижней панели ввода

### Кнопки не на одном уровне с полем ввода
Было: `Row(verticalAlignment = Alignment.Bottom)` — при росте многострочного поля ввода
кнопки прикрепления/отправки "уезжали" вниз относительно первой строки текста.
Исправлено:
- `verticalAlignment = Alignment.CenterVertically` на всей строке;
- у поля ввода добавлено `heightIn(min = 42.dp)` — та же высота, что у круглых кнопок,
  поэтому при пустом/однострочном тексте все три элемента стоят строго в один ряд.

### Меню отложенной отправки не открывалось по кнопке отправки
Причина: кнопка отправки использовала `combinedClickable(enabled = canSend, onClick, onLongClick)`.
Когда поле ввода пустое, `canSend = false` → `enabled = false` полностью отключает жест,
**включая** `onLongClick` — то есть при пустом поле долгое нажатие вообще ничего не делало.
Даже с текстом `combinedClickable` не всегда надёжно ловил long-press рядом с активным
`OutlinedTextField` (конфликт распознавания жестов между полем и кнопкой).
Исправлено: кнопка отправки теперь использует `pointerInput` с `detectTapGestures(onTap, onLongPress)`
вместо `combinedClickable` — это низкоуровневый и куда более предсказуемый способ ловить
одновременно тап и долгое нажатие, независимо от соседних элементов.

**Как это должно работать:**
1. Введите текст сообщения.
2. Обычный тап по круглой кнопке отправки (со стрелкой) — отправляет сообщение сразу, как раньше.
3. **Долгое нажатие** (удержание ~500мс) на той же кнопке — открывает диалог "Запланировать
   отправку" с пресетами (через 1 час / 3 часа / завтра утром / завтра вечером) и произвольным
   выбором даты и времени.
4. Если поле ввода пустое — кнопка справа автоматически превращается в кнопку микрофона
   (см. п.37 ниже), а не в кнопку отправки — поэтому в этом состоянии ни тап, ни долгое
   нажатие на неё не относятся к отправке/планированию текста.

## 37. Голосовые сообщения

- Новая утилита `AudioUtils` — запись через `MediaRecorder` (AAC/M4A, моно, 22050 Гц,
  32 kbps — компактно, но разборчиво), декодирование/кодирование в base64 (тот же подход,
  что и для фото в `ImageUtils` — храним прямо в документе сообщения Firestore).
- Ограничения: запись автоматически останавливается на 3 минутах; итоговый base64 не должен
  превышать ~900 КБ (запас под лимит документа Firestore в 1 МБ) — при превышении показывается
  сообщение об ошибке вместо отправки испорченного/обрезанного файла.
- `Message.voiceBase64` / `Message.voiceDurationMs` — новые поля модели.
- `MessageRepository.sendVoiceMessage(chatId, base64, durationMs)`.
- В списке чатов и в цитатах-ответах голосовое показывается как "🎤 Голосовое сообщение".
- **UI записи**: пока текстовое поле пустое, кнопка справа — микрофон. Тап запрашивает разрешение
  `RECORD_AUDIO` (если ещё не выдано) и начинает запись — панель ввода целиком заменяется на
  панель записи с пульсирующим индикатором, таймером, кнопкой отмены (корзина) и кнопкой
  подтверждения (галочка). Короткие (<0.7 сек) записи автоматически отбрасываются как случайный тап.
- **UI воспроизведения** (`VoicePlayerBubble` внутри бабла сообщения):
  - кнопка play/pause;
  - `Slider` для перемотки по записи (перетаскивание вызывает `MediaPlayer.seekTo`);
  - таймер текущей позиции/длительности;
  - бейдж скорости воспроизведения — тап переключает по кругу 1x → 1.5x → 2x → 0.5x → 1x,
    применяется через `MediaPlayer.playbackParams.setSpeed(...)` на лету, даже во время игры.
- В манифест добавлено разрешение `RECORD_AUDIO` и опциональный `uses-feature microphone`.

## 27. Индикатор прочитано/доставлено в списке чатов

Было: галочка "доставлено/прочитано" стояла в нижней строке рядом с текстом последнего
сообщения — визуально терялась и не была явно привязана ко времени.

Исправлено: индикатор перенесён **строго под метку времени последнего сообщения** (верхняя
строка, справа). Время и статус теперь стоят колонкой: сверху — время, снизу — иконка галочки.

Логика показа не изменилась, только расположение:
- Если последнее сообщение в чате отправили **вы** — под временем показывается галочка:
  одна серая (✓, доставлено) или две голубые (✓✓, прочитано).
- Если последнее сообщение **от собеседника** — под временем ничего не показывается.

Это даёт быстрый визуальный ориентир: если под временем есть галочка — значит последнее
слово осталось за вами; если пусто — ждёте (или уже получили) ответ от собеседника.
