# Stage 15 — Исчезающие сообщения (п.38) и черновики в списке чатов (п.39)

## 38. Исчезающие сообщения

- `Message.expiresAt: Long?` — момент (epoch millis), после которого сообщение удаляется.
- Таймер настраивается на уровне **чата** (поле `disappearingTtlSeconds` в документе `chats/{chatId}`),
  все новые сообщения при отправке наследуют текущее значение.
- `ChatRepository.observeDisappearingTtl(chatId)` / `setDisappearingTtl(chatId, ttl)` — чтение/запись настройки.
- `MessageRepositoryImpl.sendRawMessage` при отправке проставляет `expiresAt = now + ttl*1000`, если TTL включён.
- `observeMessages` на клиенте отфильтровывает уже истёкшие сообщения от отображения.
- `MessageRepository.deleteExpiredMessages(chatId)` — best-effort физическое удаление истёкших
  сообщений (`whereLessThan("expiresAt", now)`), вызывается раз в 15 сек, пока чат открыт
  (в `ChatViewModel.cleanupExpiredMessagesPeriodically`). Без Cloud Functions/cron это единственный
  практичный вариант очистки в текущей архитектуре (Firestore + без бэкенда).
- UI: пункт меню чата "Исчезающие сообщения" → диалог выбора (Выключено / 30 сек / 5 мин / 1 час /
  24 часа / 7 дней), подсказка-полоса под шапкой чата пока таймер включён, иконка таймера рядом
  со временем на самих сообщениях с TTL.

## 39. Черновики в главном меню

- Локальное хранение черновиков (`DraftsPreferences`, DataStore) уже было реализовано раньше
  (сохранение при вводе текста, восстановление при открытии чата, очистка при отправке).
- Добавлено: `DraftsPreferences.observeAllDrafts(): Flow<Map<chatId, text>>`.
- `ChatListViewModel` комбинирует список чатов из Firestore с потоком черновиков и прокидывает
  текст черновика в `ChatPreview.draftText`.
- `ChatListScreen`: если у чата есть непустой черновик — в списке вместо последнего сообщения
  показывается **"Черновик: ..."** (слово "Черновик:" — акцентным/красным цветом).

## Важно при использовании

Для исчезающих сообщений не задействованы Cloud Functions — очистка серверной стороны идёт лениво,
инициируется клиентом любого участника, открывшего чат. Если оба участника долго не открывают чат,
просроченные сообщения физически останутся в Firestore до следующего открытия чата кем-либо
(но в UI уже не будут показываться благодаря клиентской фильтрации).
