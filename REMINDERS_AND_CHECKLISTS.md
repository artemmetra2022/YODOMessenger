# Напоминания о сообщениях и совместные списки

Добавлено в исходники 14.10.2026. Это исходный код, а не проверенный на телефоне релиз.

## Напоминания

1. Откройте меню обычного сообщения долгим нажатием.
2. Выберите **Напомнить о сообщении**.
3. Выберите «Через час», ближайшие 20:00 или дату и время.
4. Для замены времени повторите действие; в диалоге есть отмена напоминания.
5. Нажатие на уведомление открывает чат/тему и прокручивает к исходному сообщению.

Реализация: WorkManager 2.9.1, уникальная задача для сочетания аккаунт/чат/сообщение.
Смена времени заменяет задачу. Отмена также убирает уже показанное уведомление.
В базе WorkManager нет текста переписки: только идентификаторы пользователя, чата,
сообщения и темы. Текст уведомления общий, без содержимого сообщения.

Ограничения:
- Напоминания локальные: не синхронизируются между телефонами.
- Не гарантируют точную минуту в Doze/энергосбережении; разрешение exact alarms не запрашивается.
- Нужно разрешение уведомлений и включённый канал «Напоминания о сообщениях».
- На момент срабатывания должен быть активен тот же аккаунт. Если он вышел или выбран
  другой аккаунт, задача завершается без уведомления; отложенная доставка после входа не реализована.
- WorkManager сохраняет задачи после обычного завершения процесса и перезагрузки;
  принудительная остановка приложения и ограничения производителя могут задержать выполнение.
- Содержимое/доступность сообщения не проверяются сетью в момент срабатывания.
  Если сообщение удалено, истекло либо недоступно из кэша, при открытии показывается пояснение.
- Для «Фото на один просмотр» и уже удалённых сообщений пункт меню не предлагается.

## Совместные списки групп

1. В группе откройте меню вложений и выберите **Совместный список**.
2. Введите название и пункты — по одному на строке.
3. После отправки участники могут отмечать и снимать отметки.
4. Показаны прогресс и имя участника, поставившего текущую отметку.

Лимиты: название до 100 символов, 1–20 непустых пунктов, каждый до 200 символов.
Пустые строки в форме игнорируются. Название и состав списка после отправки неизменяемы:
для исправления нужно удалить сообщение и создать новое. Полный журнал отметок не ведётся.

Данные хранятся в обычном документе сообщения:
- `checklistTitle`, `checklistItems` — неизменяемое содержание;
- `checklistCheckedBy` — индекс пункта → UID отметившего, пустая строка означает снятую отметку;
- `checklistLastItemIndex`, `checklistUpdatedBy`, `checklistUpdatedAt` — сведения последнего изменения.

Изменения идут через транзакцию Firestore. Она устанавливает нужное состояние пункта,
а не слепо переключает его при каждом повторе; параллельные изменения разных пунктов не теряются.
Каждая запись меняет только один пункт, автор отметки проверяется сервером,
время записи должно быть серверным. Посторонний, исключённый/забаненный участник,
пользователь закрытой темы не может менять список. Истёкшие и удалённые списки недоступны
для изменения. Оффлайн-изменения транзакций не ставятся в отдельную очередь — при ошибке
нужно повторить действие после восстановления сети.

Это функция групп, не личных чатов/каналов. Содержание не защищено E2EE;
об этом есть предупреждение в форме создания. Ограничения существующей схемы шифрования
остальных сообщений этим обновлением не исправляются.
Пересылка и сохранение через поток пересылки создают текстовый снимок, а не редактируемую
копию исходного списка. Экспорт истории включает заголовок и отметки списка.
Обычное удаление остаётся в рамках существующей модели мягкого удаления/архива проекта.

## Запуск и развёртывание

1. Используйте существующую конфигурацию Android/Firebase и настоящий `google-services.json`.
2. Соберите приложение через существующий GitHub Actions или локальную Android-среду.
3. Перед проверкой чек-листов разверните обновлённый `firestore.rules`:

```bash
firebase deploy --only firestore:rules
```

Это действие самостоятельно не выполнялось; продакшен Firebase не изменялся.
Новые индексы для полей чек-листов не требуются: используется существующая подписка сообщений.

### Локальные тесты правил

В `tests/firestore` есть отдельные тесты, которые работают только с проектом
`demo-yodo-checklists` на эмуляторе `127.0.0.1:8088`.

Запустите эмулятор Firestore на этом порту, затем:

```bash
cd tests/firestore
npm install
npm test
```

Если используете Firebase CLI, можно запустить команду через `emulators:exec`
с тестовой конфигурацией, в которой `emulators.firestore.port` равен 8088.
Нельзя направлять эти тесты на рабочую базу: они очищают базу тестового эмулятора.

### Unit-тесты

Добавлены `SharedChecklistTest` и `ReminderIdentityTest`. В полной Android-среде:

```bash
gradle :app:testDebugUnitTest
```

## Проверки, выполненные при подготовке архива

- Компиляция чистых Kotlin-моделей и идентификаторов напоминаний Kotlin 2.2.20.
- **9 новых JVM-тестов прошли**.
- **34 теста правил прошли на локальном эмуляторе Firestore 1.19.8**:
  создание/чтение, отметки и снятие, конкурирующие транзакции, изоляция групп,
  недопустимые данные, подмена автора/времени, закрытые темы, удалённые/истёкшие
  сообщения, неизменяемое содержание и базовые регрессии обычных сообщений.
- Изменённые Kotlin-файлы проверены синтаксическим парсером, ошибок нет.
- XML проверен на корректность, новые ключи есть в русских/английских ресурсах,
  дубликатов ключей нет.

Не выполнены: полная сборка Android/APK, запуск UI, проверка WorkManager на устройстве,
уведомлений в фоне/после перезагрузки, PIN/2FA при переходе и совместной работы двух телефонов.
Статический разбор не заменяет проверку Android API и Compose при полной сборке.

## Проверка на устройствах перед релизом

- Android 13+: разрешение уведомлений, отказ и повторное включение; отключённый канал.
- Напоминание через час/своё время, замена, отмена, перезапуск и перезагрузка.
- Переход к старому сообщению/теме из холодного и тёплого запуска; PIN/2FA.
- Выход/смена аккаунта до срабатывания, недоступное/удалённое сообщение.
- Два участника группы: создание списка, отметка, снятие и одновременные отметки.
- Потеря сети при отметке, закрытие темы, исключение/бан участника.
- Пересылка снимка списка, удаление, истечение TTL, экспорт, русский/английский интерфейс.
