ИДЕИ ДЛЯ УЛУЧШЕНИЯ YODO MESSENGER
=================================

Актуализировано 19.10.2026 по исходникам из архива YODOMessenger-widgets.zip
(599 файлов, виджеты рабочего стола и раздел «Школа» уже включены).

Основание: статическая проверка исходников, ресурсов, firestore.rules,
GitHub Actions и документов проекта (поиск по коду). Приложение не собиралось
и не запускалось, тесты не выполнялись, деплой Firebase не проверялся.
«Есть в коде» не означает «протестировано и доступно пользователям».
Что не удалось подтвердить поиском, помечено «не найдено» — это не доказательство
отсутствия, а повод проверить вручную.

ЧТО УЖЕ ЕСТЬ В КОДЕ — НЕ ПЛАНИРОВАТЬ ПОВТОРНО С НУЛЯ
====================================================
Сообщения и чаты
- Очередь исходящего текста (TextMessageOutbox): шифрование AES-GCM ключом
  Keystore, раздельно по аккаунтам, до 200 сообщений, очередь на каждый чат,
  постоянный ID запроса, возобновление после перезапуска, лимит 8 сообщений за
  10 секунд выдерживается ожиданием. Только текст. Подробности:
  MESSAGES_AND_RECEIPTS_CHANGES.md.
- Мультивыбор сообщений, ответы, пересылка, реакции, редактирование, диалог
  «Информация о сообщении», запланированная отправка, исчезающие сообщения.
- Избранное: личный сохранённый чат (getOrCreateSavedChat). Маршрут
  SavedMessages в навигации остаётся заглушкой и не используется.
- Свайпы в списке чатов: закрепить, звук, архив, очистить, удалить, скрыть.
- Голосовые: скорости 0.5x/1x/1.5x/2x, ползунок позиции, отмена записи.
- Упоминания @username в группах и каналах с отдельными каналами уведомлений
  (MENTIONS_AND_NOTIFICATION_ACTIONS.md).
- Тихие часы (по времени суток, учитывают переход через полночь), пауза,
  скрытие превью. Быстрый ответ, «Прочитано» и локальное «Отключить звук» в
  уведомлениях; доступность действий зависит от типа чата и прав (тесты в
  NotificationPolicyTest).
- Контакты из телефонной книги (ContactsViewModel, READ_CONTACTS).
- Список устройств и завершение сессий (DevicesViewModel.terminateSession).
- QR-вход (QrLoginScreen, web/qr-login.js), веб-панель модерации (web/admin.*).
Каналы и группы
- Публичные/модерируемые/скрытые каналы, роли, форумные темы, комментарии,
  посты с Markdown, статистика канала, ссылка-приглашение в канал
  (yodo://channel/<id>), жалобы, апелляции, журнал действий админов.
Виджеты (WIDGETS.md)
- «Непрочитанные», «Погода», «Погода и непрочитанные», «Школа». Glance,
  размеры 1×1…4×4, обновление по push, сворачиванию и по расписанию.
Школа
- Новости, учителя и страницы учителей, расписание звонков с живым статусом
  урока, отсчёт до каникул (дату может задать админ), опросы, викторина, игра,
  отзывы, FAQ, раздел для родителей, админ-раздел, режим учителя.
Доска (CANVAS_*.md, BOARD_*.md)
- Этапы 1–6: локальная доска, Nearby для двух устройств, формулы (школьное
  подмножество LaTeX), онлайн-режим по коду приглашения, общая доска чата,
  библиотека досок с мультивыбором.
Обновления

  краткая история релизов, release-сборка по push в main.
Тесты

1. НАДЁЖНОСТЬ СООБЩЕНИЙ И ИСТОРИЯ
---------------------------------
- Очередь исходящих есть только для текста. Для фото, альбомов, документов,
  голосовых и пересылки аналога не найдено: проверить, что случается при
  потере сети и перезапуске посреди отправки.
- В TextMessageOutbox найден ручной retry; автоматический backoff не подтверждён.
- Дедупликация по постоянному ID подтверждена для текстового пути; для
  остальных путей отправки проверить отдельно.
- Пагинация истории не сделана: observeMessages слушает всю историю
  (orderBy timestamp без limit), подгрузки старых сообщений не найдено.
  Это растёт вместе с чатом по числу чтений Firestore и времени открытия.
- Сохранять позицию прокрутки при подгрузке, открывать старое сообщение без
  загрузки всей истории.

2. БЕЗОПАСНОСТЬ И ШИФРОВАНИЕ
----------------------------
Пакет безопасности от 14.10.2026 (fail-closed текст, отпечатки, TOFU,
изоляция аккаунтов) внесён в исходники; детали и ограничения —
PRIVATE_TEXT_SECURITY.md. Проверки на устройствах пока нет.
- Проверить fail-closed отправку: нет ключа, смена ключа, ошибка Keystore;
  открытый текст не уходит, черновик сохраняется.
- Проверить очистку старых lastMessagePlain (админ-скрипт по умолчанию DRY_RUN).
- Схема не имеет ratchet: CryptoManager сам указывает, что нет forward secrecy,
  E2EE для групп и медиа и мультиустройства. Охват только личные тексты.
- Ключи при смене аккаунта, новом устройстве, переустановке.
- Проверить логи, push, превью и резервные копии на открытый текст.
Не найдено в коде (кандидаты):
- Биометрия вместо PIN для приложения и скрытых чатов.
- Уведомление о входе с нового устройства (сейчас только код 2FA на почту).
- Passkeys через Credential Manager.
- Удалённое стирание данных потерянного устройства (завершение сессии есть).
  Стирание возможно только best-effort, когда устройство выйдет на связь.

3. МОДЕРАЦИЯ И АНТИСПАМ
-----------------------
- config/moderationPolicy описан в firestore.rules (читают все авторизованные,
  пишут админы с правом settings), но в Kotlin-коде не читается; медленного
  режима в приложении нет. Комментарий в правилах прямо говорит, что клиент
  обязан применять лимиты, а сами правила частоту считать не умеют.
- Лимиты на устройстве обходятся модифицированным APK. Нужна серверная
  проверка (Cloud Function или правила на метках времени) и тесты обхода.
- Не смешивать moderationPolicy и работающий клиентский autoModeration.
- Медленный режим групп: права, область, серверное время, понятный таймер.
- Проверить веб-модерацию (роли, санкции, обжалования, шаблоны, эскалация)
  после деплоя; подтверждение санкций оставить за администратором.
