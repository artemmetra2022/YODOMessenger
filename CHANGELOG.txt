ИСТОРИЯ ИЗМЕНЕНИЙ YODO MESSENGER
================================

12 сентября 2026
- Веб-админ-панель: «Жалобы» — расширенная система модерации сообщений.
  Фильтрация жалоб по типам (спам, оскорбления, NSFW, реклама и т.д.) с
  диаграммой распределения: горизонтальные полосы по убыванию с числами и
  процентами, клик по полосе включает фильтр; фильтр по типу независим от
  фильтра по статусу.
- Веб-админ-панель: «Жалобы» — просмотр контекста жалобы: 3 сообщения до и
  после нарушителя с авторами и временем, целевое сообщение подсвечено
  (кнопка доступна и по уже закрытым жалобам). Если сообщение уже удалено,
  показывается сохранённый в жалобе текст.
- Веб-админ-панель: «Жалобы» — массовое удаление сообщений пользователя по
  периоду во всех чатах: поиск через collection-group запрос, предпросмотр
  найденного, подтверждение, мягкое удаление батчами по 400 (в чатах
  остаётся «Сообщение удалено администратором»), пересчёт превью чатов,
  запись в аудит.
- Android/веб: новые причины жалоб NSFW («Неприемлемый контент») и
  ADVERTISING («Реклама») — ReportReason.kt и REPORT_REASONS в админке.
  Причины хранятся по имени, обратная совместимость сохранена.
- Firestore: сквозное чтение коллекции messages двумя главными админами —
  оно нужно для контекста жалоб и массового удаления (правила чата
  разрешают чтение только участникам); новый collection-group индекс
  messages(senderId, timestamp) в обоих направлениях.
- Аудит: новый тип записи REPORT_BULK_MESSAGES_DELETED.
- Веб-админ-панель: «Жалобы» — причины удаления сообщений: стандартный набор
  (спам, оскорбление, NSFW, нарушение правил, другое) в окне выбора при
  удалении — из жалобы и при массовом удалении. Выбранная причина сохраняется
  в истории удалённых и в журнале аудита.
- Веб-админ-панель: «Жалобы» — история удалённых сообщений: архив мягко
  удалённых сообщений (включая удаления модераторов из Android-приложения) с
  восстановлением в течение 30 дней и кнопкой очистки записей старше 30 дней.
  Восстанавливается текст и (если умещается в лимит документа Firestore) медиа;
  иначе запись помечается mediaSkipped.
- Веб-админ-панель: «Жалобы» — автофильтр сообщений: паттерны автоудаления
  (ссылка/подстрока, домен, слово, регулярное выражение) с указанием причины,
  проверка последних 200 сообщений всех чатов и удаление найденного.
  Android-приложение проверяет текст при отправке — включая личные (E2EE)
  чаты, потому что проверяется открытый текст до шифрования.
- Android: мягкое удаление сообщений (deleteMessage/deleteMessages) и
  автофильтр при отправке сохраняют копию сообщения в архив deletedMessages
  (MessageRepositoryImpl.archiveDeletedMessage); «тихое» удаление
  (hardDeleteMessage) запись в архив не создаёт — по своему назначению.
- Firestore: новые правила — config/autoModeration (чтение всем авторизованным,
  запись двум админам) и корневая коллекция deletedMessages (создание —
  автором удаления, чтение/восстановление/очистка — админам); collection-group
  индекс messages(timestamp) (single-field index controls) для сканирования
  автофильтром.
- Аудит: новые типы MESSAGE_DELETED_WITH_REASON, MESSAGE_RESTORED,
  AUTO_FILTER_RULE_SAVED, AUTO_FILTER_MESSAGES_DELETED, DELETED_HISTORY_CLEANED.

11 сентября 2026
- Веб-админ-панель: новый раздел «Канал» — публикация постов в официальный
  канал YodoMessenger (chats/yodo_official_channel) прямо из панели, без
  веб-мессенджера: текст, тема поста плиткой (формат ⟦news:Тема⟧тело, 1:1 с
  NewsTopic.kt), прикрепление фото (1 или альбом до 10, сжатие в canvas под
  общий лимит документа), тихая публикация (без push), предпросмотр в стиле
  приложения, правка текста/темы, закрепление и удаление, список последних
  постов с просмотрами/комментариями. Запись документа сообщения и превью чата
  идёт одним батчем 1:1 с sendRawMessage в Android; push подписчикам рассылает
  штатный механизм воркера (notified=false).
- Веб-админ-панель: новый раздел «Push-центр» — произвольные рассылки
  уведомлений: аудитория «подписчики школьных пушей» / «все пользователи» /
  «один пользователь по UID», история последних 50 рассылок со статусом
  очереди и счётчиком доставки, отмена ещё не отправленной рассылки.
  Очередь — корневая коллекция pushBroadcasts, отправляет push-воркер
  (новый шаг sendAdminBroadcasts; данные с type=school, новых типов
  уведомлений клиентам не требуется).
- Firestore: правило доступа к pushBroadcasts (чтение/создание/удаление —
  только два главных админа; notified пишет воркер через Admin SDK).
- Аудит: новые типы записей CHANNEL_POST_ADDED, CHANNEL_POST_DELETED,
  ADMIN_BROADCAST_QUEUED.

9 сентября 2026
- Веб-админ-панель: новости — отложенная публикация по времени (без Cloud
  Functions: push-воркер каждые ~5 минут публикует schoolNews с наступившим
  publishAt), черновики (published=false — ученикам не видны), кнопка
  «Опубликовать сейчас», ручная повторная отправка push.
- Веб-админ-панель: опросы — завершение/переоткрытие (closed), создание без
  push (тихое), ручная отправка push. В приложении завершённый опрос виден
  с бейджем «Завершён» и результатами, голосование запрещено на трёх
  уровнях: UI, репозиторий, правила Firestore.
- Push-воркер: новый шаг publishScheduledSchoolNews; неопубликованные
  новости не рассылаются (notified не трогается).
- Android: SchoolNews.published и SchoolPoll.closed с обратной
  совместимостью (отсутствие поля = опубликовано/открыт); новые типы
  записей аудита для журнала.
- Веб-админ-панель: раздел «Жалобы» — сквозная очередь всех жалоб из всех
  чатов (фильтры по статусу, CSV-экспорт, бейдж в сводке), решения:
  удалить сообщение (мягкое удаление, как в приложении, с пересчётом
  превью чата), заблокировать автора (globalBlocks + push), отклонить.
- Веб-админ-панель: раздел «Пользователи» — поиск по имени/@username/
  YODO-ID, карточка профиля (email, дата регистрации, UID) с live-статусом
  блокировки и кнопками блокировки/разблокировки.
- Веб-админ-панель: раздел «Блокировки» — список глобально заблокированных
  аккаунтов с причинами и разбаном, ручная блокировка по UID.
- Блокировка/разблокировка из панели шлёт push через очередь
  moderationNotifications (форматы 1:1 с UserRepositoryImpl).
- Правила Firestore: два главных админа могут закрывать жалобы в любом
  чате (белый список полей рассмотрения); Android-клиент показывает новые
  типы записей аудита (решения по жалобам) в журнале.
