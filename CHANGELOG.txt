ИСТОРИЯ ИЗМЕНЕНИЙ YODO MESSENGER
================================

13 сентября 2026 — МОДЕРАЦИЯ: ШАБЛОНЫ, КОНТЕКСТ, ЭСКАЛАЦИЯ, АНТИСПАМ (ТЕСТ)
===========================================================================
ВАЖНО: всё ниже в этом разделе пока ТЕСТОВОЕ — нужна проверка на
живом проекте после деплоя (firebase deploy --only firestore:rules и
--only hosting).

1) Шаблоны причин (раздел «Жалобы» → карточка «Шаблоны причин»)
   - Три вида шаблонов: санкция/блокировка, отказ по обжалованию,
     удаление сообщения. Хранятся в config/reasonTemplates.
   - В форме мягких санкций появился селект шаблона: выбрал —
     текст сам подставился в причину.
   - Отказ по обжалованию больше не спрашивается браузерным prompt():
     нормальное окно с выбором шаблона и редактируемым текстом.
   - Есть набор по умолчанию (8 шаблонов), работает сразу.

2) Контекст нарушений в обжалованиях
   - В карточке обжалования теперь видно: сколько было жалоб,
     предупреждений, мутов и банов, а также последнюю меру с датой.
   - Считается по warnings, blockHistory и жалобам; если прав или
     индекса не хватает — показывает нули и не ломает список.

3) Авто-эскалация санкций (подсказка, а не автомат)
   - После выдачи предупреждения: если их уже N (по умолчанию 3) —
     панель предлагает выдать мут (по умолчанию на 24 ч).
   - После выдачи мута: если мутов уже N (по умолчанию 3) —
     предлагает блокировку аккаунта.
   - Решение всегда подтверждает админ; ничего не применяется без
     подтверждения. В аудит пишется событие SANCTION_ESCALATED.
   - Если мут/бан уже активен — предложение не показывается.

4) Антиспам-правила из панели (карточка «Политика модерации»)
   - Настраивается: лимит сообщений в минуту, макс. длина сообщения,
     медленный режим (сек), запрет ссылок новым аккаунтам и окно
     «нового аккаунта» в часах, плюс пороги эскалации.
   - Сохраняется в config/moderationPolicy, есть кнопка сброса.
   - ВАЖНО: само ограничение применяет клиент при отправке — в
     Android-приложении нужно читать этот документ в
     MessageRepositoryImpl (без Cloud Functions rules частоту отправок
     считать не умеют). Панель уже готова и хранит настройки.

Техническое:
   - firestore.rules: добавлены config/reasonTemplates и
     config/moderationPolicy — чтение авторизованным, запись только
     роли с правом settings.
   - Новые события аудита: REASON_TEMPLATE_SAVED, MOD_POLICY_SAVED,
     SANCTION_ESCALATED.
   - Для стабильного подсчёта контекста полезно добавить индексы:
     warnings.userId, blockHistory.userId, collectionGroup reports
     .targetUserId.


13 сентября 2026 — ТЕСТ (всё ниже пока тестовое, нужна проверка на живом проекте)
- Веб-админ-панель: навигация по адресу (#раздел) и возврат в последний
  открытый раздел после перезагрузки; быстрый переход (Ctrl+K),
  горячие клавиши, светлая/тёмная тема, бейджи с числом неразобранных
  жалоб и вопросов в боковом меню.
- Веб-админ-панель: «Аудит» — поиск по тексту, фильтры по типу действия и
  периоду, лимит записей и CSV-экспорт журнала.
- Веб-админ-панель: роли админов (owner / admin / moderator / support /
  editor / viewer). Роли хранятся в config/adminRoles, разделы и кнопки
  скрываются по правам, выдача/отзыв роли пишется в аудит.
- Firestore: роли теперь проверяются на сервере, а не только в интерфейсе:
  в firestore.rules добавлены функции adminRole() / rolePerms() / hasPerm() /
  isAnyAdmin(), и доступ к жалобам, сообщениям, блокировкам, поддержке,
  настройкам, FAQ, новостям и аудиту разграничен по правам
  (moderation, users.view, users.block, support, content, content.faq,
  settings, audit, destructive, roles). Выдавать роли может только
  владелец (два главных админа). ВАЖНО: после обновления нужно
  выполнить firebase deploy --only firestore:rules.
- Веб-админ-панель и Android: блокировки на срок (1 час … 30 дней или
  бессрочно): globalBlocks.expiresAt / durationMs, автоснятие истёкших
  блокировок каждые 5 минут при открытой панели, срок виден в списке
  блокировок; в приложении истёкшая блокировка больше не действует
  (GlobalBlock.isExpired).
- Веб-админ-панель: «Жалобы» — взятие жалобы в работу (claimedBy),
  бейдж «в работе у …», предупреждение при попытке решить жалобу,
  взятую другим админом, автосброс забытого захвата через 30 минут.
- Веб-админ-панель: мягкие санкции в разделе «Блокировки» — мут
  (запрет писать, кроме чата поддержки), теневой бан и
  предупреждение. Срок и причина как у блокировки, автоснятие по
  истечении, списки активных мутов/теневых банов и история
  предупреждений со счётчиком на пользователя. Новые коллекции
  mutes/{uid}, shadowBans/{uid}, warnings/{id}; мут проверяется в правилах
  на создание сообщений (hasActiveMute), о муте приходит push,
  теневой бан — без уведомления.
- Веб-админ-панель: новый раздел «Обжалования» — отдельная очередь
  заявлений заблокированных (жалобы с reason=APPEAL). Видно, активна
  ли блокировка и за что она вынесена; «Снять блокировку» убирает
  бан, мут и теневой бан сразу, «Отказать» требует причины; решение
  уходит пользователю push-уведомлением и пишется в аудит.
  Обжалования больше не смешиваются с обычными жалобами.
- Веб-админ-панель: «Жалобы» — фильтры по периоду (сутки / 7 / 30
  дней), «только взятые мной» и сортировка (новые / старые / по
  числу жалоб на нарушителя), а также массовые действия: выбор
  жалоб галочками (или «выбрать все на рассмотрении»), затем
  отклонить / удалить сообщения / заблокировать авторов одним
  действием (с подтверждением, архивом удалённых, пересчётом
  превью чата и итоговой записью в аудит).
- Аудит: новые типы записей — мут/снятие мута, теневой бан/снятие,
  предупреждение, обжалование удовлетворено/отклонено, три типа
  массовых действий по жалобам, выдача/отзыв роли, автоснятие
  санкции по сроку, взятие/возврат жалобы.
- Ограничение: Cloud Functions не используются (бесплатный план Spark),
  поэтому автоснятие сроков работает при открытой панели либо через
  push-воркер; фактический запрет на отправку дают правила Firestore.
  Скрытие сообщений теневого бана на стороне Android-клиента пока не
  сделано — сейчас флаг используется как метка для модераторов.

12 сентября 2026
- Веб-админ-панель: «Блокировки» и карточка пользователя — причины блокировки:
  стандартный набор (спам, оскорбления, NSFW, мошенничество, нарушение правил,
  обход блокировки, другое) с описаниями и своим текстом для «Другое». Код
  причины пишется в globalBlocks.reasonCode, а каждая блокировка и
  разблокировка — в новый журнал blockHistory (пишут и веб-панель, и
  Android-приложение).
- Веб-админ-панель: расширенная карточка пользователя — последние 5 входов
  (сессии устройств), число отправленных сообщений, число жалоб на
  пользователя, список групп и каналов, история блокировок и связанные записи
  журнала аудита. IP-адреса не собираются: Firestore не отдаёт IP клиента, а
  сессии (users/{uid}/sessions) его не хранят.
- Веб-админ-панель: «Обзор» — аналитика активности за 30 дней: график
  «сообщений в день» по всему приложению (структура данных [{ date, count }]),
  числа берутся агрегатом getCountFromServer по collection-group messages.
- Firestore: правила — админам разрешено чтение любого чата (для списка групп и
  каналов пользователя) и сессий любого пользователя; новая корневая коллекция
  blockHistory (чтение/создание — двум админам). Индексы: составной
  adminAuditLog(targetUserId, timestamp DESC) и single-field index controls для
  messages.senderId и reports.targetUserId (нужны для счётчиков в карточке).
- Веб-админ-панель: «Жалобы» — расширенная система модерации сообщений.
  Фильтрация жалоб по типам (спам, оскорбления, NSFW, реклама и т.д.) с
  диаграммой распределения: горизонтальные полосы по убыванию с числами и
  процентами, клик по полосе включает фильтр; фильтр по типу независим от
  фильтра по статусу.
- Веб-админ-панель: «Жалобы» — просмотр контекста жалобы: 3 сообщения до и
  после нарушителя с авторами и временем, целевое сообщение подсвечено
  (кнопка доступна и по уже закрытым жалобам). Если сообщение уже удалено,
  показывается сохранённый в жалобе текст.
- Веб-админ-панель: «Жалобы» — массовое удаление сообщений пользователя по
  периоду во всех чатах: поиск через collection-group запрос, предпросмотр
  найденного, подтверждение, мягкое удаление батчами по 400 (в чатах
  остаётся «Сообщение удалено администратором»), пересчёт превью чатов,
  запись в аудит.
- Android/веб: новые причины жалоб NSFW («Неприемлемый контент») и
  ADVERTISING («Реклама») — ReportReason.kt и REPORT_REASONS в админке.
  Причины хранятся по имени, обратная совместимость сохранена.
- Firestore: сквозное чтение коллекции messages двумя главными админами —
  оно нужно для контекста жалоб и массового удаления (правила чата
  разрешают чтение только участникам); новый collection-group индекс
  messages(senderId, timestamp) в обоих направлениях.
- Аудит: новый тип записи REPORT_BULK_MESSAGES_DELETED.
- Веб-админ-панель: «Жалобы» — причины удаления сообщений: стандартный набор
  (спам, оскорбление, NSFW, нарушение правил, другое) в окне выбора при
  удалении — из жалобы и при массовом удалении. Выбранная причина сохраняется
  в истории удалённых и в журнале аудита.
- Веб-админ-панель: «Жалобы» — история удалённых сообщений: архив мягко
  удалённых сообщений (включая удаления модераторов из Android-приложения) с
  восстановлением в течение 30 дней и кнопкой очистки записей старше 30 дней.
  Восстанавливается текст и (если умещается в лимит документа Firestore) медиа;
  иначе запись помечается mediaSkipped.
- Веб-админ-панель: «Жалобы» — автофильтр сообщений: паттерны автоудаления
  (ссылка/подстрока, домен, слово, регулярное выражение) с указанием причины,
  проверка последних 200 сообщений всех чатов и удаление найденного.
  Android-приложение проверяет текст при отправке — включая личные (E2EE)
  чаты, потому что проверяется открытый текст до шифрования.
- Android: мягкое удаление сообщений (deleteMessage/deleteMessages) и
  автофильтр при отправке сохраняют копию сообщения в архив deletedMessages
  (MessageRepositoryImpl.archiveDeletedMessage); «тихое» удаление
  (hardDeleteMessage) запись в архив не создаёт — по своему назначению.
- Firestore: новые правила — config/autoModeration (чтение всем авторизованным,
  запись двум админам) и корневая коллекция deletedMessages (создание —
  автором удаления, чтение/восстановление/очистка — админам); collection-group
  индекс messages(timestamp) (single-field index controls) для сканирования
  автофильтром.
- Аудит: новые типы MESSAGE_DELETED_WITH_REASON, MESSAGE_RESTORED,
  AUTO_FILTER_RULE_SAVED, AUTO_FILTER_MESSAGES_DELETED, DELETED_HISTORY_CLEANED.

11 сентября 2026
- Веб-админ-панель: новый раздел «Канал» — публикация постов в официальный
  канал YodoMessenger (chats/yodo_official_channel) прямо из панели, без
  веб-мессенджера: текст, тема поста плиткой (формат ⟦news:Тема⟧тело, 1:1 с
  NewsTopic.kt), прикрепление фото (1 или альбом до 10, сжатие в canvas под
  общий лимит документа), тихая публикация (без push), предпросмотр в стиле
  приложения, правка текста/темы, закрепление и удаление, список последних
  постов с просмотрами/комментариями. Запись документа сообщения и превью чата
  идёт одним батчем 1:1 с sendRawMessage в Android; push подписчикам рассылает
  штатный механизм воркера (notified=false).
- Веб-админ-панель: новый раздел «Push-центр» — произвольные рассылки
  уведомлений: аудитория «подписчики школьных пушей» / «все пользователи» /
  «один пользователь по UID», история последних 50 рассылок со статусом
  очереди и счётчиком доставки, отмена ещё не отправленной рассылки.
  Очередь — корневая коллекция pushBroadcasts, отправляет push-воркер
  (новый шаг sendAdminBroadcasts; данные с type=school, новых типов
  уведомлений клиентам не требуется).
- Firestore: правило доступа к pushBroadcasts (чтение/создание/удаление —
  только два главных админа; notified пишет воркер через Admin SDK).
- Аудит: новые типы записей CHANNEL_POST_ADDED, CHANNEL_POST_DELETED,
  ADMIN_BROADCAST_QUEUED.

9 сентября 2026
- Веб-админ-панель: новости — отложенная публикация по времени (без Cloud
  Functions: push-воркер каждые ~5 минут публикует schoolNews с наступившим
  publishAt), черновики (published=false — ученикам не видны), кнопка
  «Опубликовать сейчас», ручная повторная отправка push.
- Веб-админ-панель: опросы — завершение/переоткрытие (closed), создание без
  push (тихое), ручная отправка push. В приложении завершённый опрос виден
  с бейджем «Завершён» и результатами, голосование запрещено на трёх
  уровнях: UI, репозиторий, правила Firestore.
- Push-воркер: новый шаг publishScheduledSchoolNews; неопубликованные
  новости не рассылаются (notified не трогается).
- Android: SchoolNews.published и SchoolPoll.closed с обратной
  совместимостью (отсутствие поля = опубликовано/открыт); новые типы
  записей аудита для журнала.
- Веб-админ-панель: раздел «Жалобы» — сквозная очередь всех жалоб из всех
  чатов (фильтры по статусу, CSV-экспорт, бейдж в сводке), решения:
  удалить сообщение (мягкое удаление, как в приложении, с пересчётом
  превью чата), заблокировать автора (globalBlocks + push), отклонить.
- Веб-админ-панель: раздел «Пользователи» — поиск по имени/@username/
  YODO-ID, карточка профиля (email, дата регистрации, UID) с live-статусом
  блокировки и кнопками блокировки/разблокировки.
- Веб-админ-панель: раздел «Блокировки» — список глобально заблокированных
  аккаунтов с причинами и разбаном, ручная блокировка по UID.
- Блокировка/разблокировка из панели шлёт push через очередь
  moderationNotifications (форматы 1:1 с UserRepositoryImpl).
- Правила Firestore: два главных админа могут закрывать жалобы в любом
  чате (белый список полей рассмотрения); Android-клиент показывает новые
  типы записей аудита (решения по жалобам) в журнале.
