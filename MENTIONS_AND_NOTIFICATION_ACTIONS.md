# Упоминания и быстрые действия уведомлений

## Что добавлено в Android-клиент

### @username в группах и каналах
- При наборе `@` или начала имени над полем ввода появляются до трёх подходящих участников с username. Нажатие вставляет имя и пробел. Используется уже загруженный список участников, глобальный поиск посторонних пользователей не выполняется.
- Упоминания в тексте сообщения выделены полужирным. Формат — как в профиле: 3–20 латинских букв, цифр или `_`. Регистр не важен, совпадение строгое: `@user_long` не уведомляет `@user`; почта и URL вида `/@user` не считаются упоминаниями.
- Входящий push группы/канала проверяется на username текущего аккаунта. Если имя найдено — отдельный стек «@ Упоминание · название чата», отдельно от обычных сообщений этого чата.
- Созданы отдельные системные каналы «Упоминания @»: звук/вибрация работают независимо. Настройки приложения → Уведомления → Уведомления об упоминаниях открывает соответствующий канал в Android.
- Глобальное отключение уведомлений, пауза, тихие часы, скрытие превью и серверное отключение уведомлений чата не обходятся. Упоминание не снимает запрет пользователя на уведомления.

### «Отключить звук» прямо из уведомления
- Отключает звук и вибрацию конкретного чата для текущего аккаунта на этом устройстве. Следующие уведомления остаются видимыми, но тихими. Это НЕ серверное отключение уведомлений чата и НЕ отключение уведомлений всем участникам.
- Работает без сети, сохраняется после перезапуска. Убирает текущие уведомления чата, не помечая сообщения прочитанными.
- В следующем тихом уведомлении вместо неё показано «Включить звук». Можно также отменить все такие локальные отключения через Настройки → Уведомления → Вернуть звук чатам (с подтверждением). Общие ограничения при этом сохраняются.

### Быстрые действия групп и каналов
- Личный чат / группа: «Прочитано», «Ответить», «Отключить звук».
- Канал, обычный подписчик: «Прочитано» и «Отключить звук»; публикация недоступна.
- Канал, владелец/администратор/роль POST_MESSAGES: дополнительно «Опубликовать». Для официального канала — только доверенным администраторам.
- При скрытом превью быстрый ответ не предлагается ни в одном типе чата.
- Неизвестные типы чатов, вышедшие/заблокированные участники не получают быстрых действий.
- Перед действием повторно проверяются аккаунт и актуальные серверные права. PendingIntent привязан к аккаунту, чату, действию и теме; флаг из push не даёт права публикации.
- Inline-ответ сохраняется в той же зашифрованной FIFO-очереди, что обычный текст. Подтверждение честное: «Ответ добавлен в очередь отправки», НЕ «отправлен» до сервера. Состояние отправки/ошибка доступны в чате. Тема передаётся, если её ID есть в push.
- «Прочитано» — явное действие прочтения всего чата, только от текущего пользователя. Операции счётчиков/receipt дополнительно привязаны к ожидаемому аккаунту, включая смену аккаунта во время сетевого ожидания.
- История уведомлений изолирована по аккаунтам, чату и обычным сообщениям/упоминаниям. Открытие чата очищает оба стека.

## Важное ограничение серверной части
В предоставленном архиве и публичной ветке репозитория нет `push-worker/`, хотя `.github/workflows/send-push-notifications.yml` запускает `push-worker/index.js`. Серверный обработчик не восстановлен и не заменён догадками; его текущую реализацию проверить невозможно. Эта задача меняет клиент, а не развёртывает новую серверную доставку.

С имеющимися push-полями `chatId`, `senderName`, `messageText` клиент распознаёт @упоминание из ПОЛНОГО переданного текста группового сообщения. Для push без текста, с обрезанным текстом после упоминания или со скрытым содержимым на сервере такой fallback может не определить упоминание. Если профиль не удалось загрузить, уведомление показывается обычным, а не выдаётся за точно распознанное упоминание.

Для надёжной серверной маркировки обработчик должен направлять доверенный data-only FCM-пакет адресату:

```json
{
  "data": {
    "type": "mention",
    "recipientId": "UID_АДРЕСАТА",
    "chatId": "ID_ЧАТА",
    "senderId": "UID_АВТОРА",
    "senderName": "Имя автора",
    "messageText": "@username, посмотри рисунок",
    "topicId": "ID_ТЕМЫ_ЕСЛИ_ЕСТЬ"
  }
}
```

Не отправлять поле `notification`: в фоне Android может показать его сам, в обход клиентских кнопок/тишины. Сервер должен проверять участников, исключать автора, не создавать отдельный дублирующий обычный push тому же адресату и соблюдать серверные настройки mute. Пакеты `type=mention` с чужим recipientId клиент отбрасывает. Частоту/гарантии/дедупликацию доставки действующего обработчика эти исходники не меняют; существующий workflow настроен на ~5 минут, не realtime.

Приватные E2EE-сообщения не расшифровываются и не загружаются на сервер ради поиска упоминаний. Автоматическое распознавание @ из текста в этой реализации касается групп/каналов. Для полноценной сквозной проверки push и расширения сервера требуется исходник используемого push-worker.

## Проверки
- 24 новых JVM-теста: границы/регистр/алфавит/длина username, почта/URL, несколько имён, точные диапазоны, подсказки, подстановка, роли каналов, неизвестный чат, бывший участник, скрытое превью, независимость звука/вибрации — пройдены.
- 45 прежних JVM-тестов очереди/слияния сообщений, статусов, badge, истории версий и выбора досок — повторно пройдены (соответствующие чистые Kotlin-модули не изменялись).
- NotificationHelper проверен Kotlin-компилятором с Android 34 API и настоящим AndroidX Core 1.13.1; классы приложения подставлены заглушками. Это проверка API/типов helper, НЕ сборка приложения.
- Синтаксис изменённых Kotlin-файлов и XML ресурсов проверен.
- Локальные HTML-макеты подсказок и карточек действий проверены при ширине 320/390 px. Это не реальный рендер системной шторки: порядок/число видимых кнопок зависит от Android/OEM и развёрнутости уведомления.
- APK не собран, Android/FCM/RemoteInput и смена роли/аккаунта на настоящем устройстве не тестировались. Нужны CI-сборка и проверка на двух телефонах: группа, канал-читатель, канал-админ, скрытое превью, звук/вибрация, тихие часы, офлайн-очередь, несколько аккаунтов и длинное сообщение с @ в конце.

Предыдущие изменения досок, истории версий и бренд-иллюстрации сохранены. Firestore rules и данные на сервере этой задачей не изменялись, ничего не развёртывалось.
