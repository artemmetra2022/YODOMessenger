# Исправление синего счётчика непрочитанных

## Что исправлено

1. Сброс unreadCounts больше не находится внутри транзакции персональных readBy /
   deliveredTo. Отказ подтверждения, старые правила или настройка приватности не
   должны блокировать отдельный сброс синего счётчика.
2. Экран отдельно наблюдает счётчик чата и темы. Изменение одного лишь счётчика
   повторно запускает синхронизацию, даже если ID видимых сообщений уже были
   подтверждены ранее. Нулевой счётчик не вызывает постоянных транзакций по таймеру.
3. Сброс делается только для текущего хвоста, реально показанного в активном окне.
   Серверная транзакция заново проверяет последний ID. Новое входящее между просмотром
   и записью не стирается старым сбросом. Просмотр истории не обнуляет новый хвост.
4. Для старых документов без lastMessageId есть проверка времени и отправителя по
   реальным показанным документам на сервере — без доверия только клиентскому времени.
5. При просмотре темы одновременно обнуляется счётчик темы и из общего счётчика группы
   вычитается именно её непрочитанное количество. Другие темы остаются непрочитанными;
   повторный просмотр не вычитает счётчик второй раз.
6. Исправлены правила отправки в тему обычным участником: новый lastMessageId был
   добавлен клиентом в предыдущей версии, но отсутствовал в whitelist правил.
7. Бейдж больше не скрыт принудительно у каналов. Официальный канал больше не заменяет
   полученный unreadCounts текущего пользователя постоянным нулём. Читатель может
   сбросить только собственный счётчик официального канала, не меняя чужие значения,
   содержимое или настройки канала.
8. Числа читаются как Number с нормализацией, включая Int/Long, отрицательные и
   переполненные значения. Отдельно исправлен маппинг счётчика тем.
9. При сворачивании или закрытии экрана список видимых сообщений для счётчика очищается.
   Показ удалённого/нерасшифрованного плейсхолдера может убрать его синий бейдж, но не
   выставляет публичное подтверждение чтения нерасшифрованного содержимого.

## Установка

Обновить правила **перед** установкой нового APK:

```sh
firebase deploy --only firestore:rules
```

Собрать APK по существующему workflow проекта и обновить приложения. Изменения не
публиковались в GitHub и не разворачивались в рабочем Firebase автоматически.
Архив содержит полный проект со всеми предыдущими исправлениями.

## Проверки

- 21 новый тест Firestore Emulator: увеличение 1→3, сброс независимо от read receipts,
  сохранение чужого счётчика, повторное входящее, чтение истории, неадминская отправка
  в тему, общий счётчик нескольких тем, старый документ без ID, права официального
  канала и гонка с новым входящим во время сброса.
- Весь набор: 174 теста Firestore Emulator — 34 checklist, 42 private-text-security,
  20 canvas, 31 shared-board, 26 message-receipts, 21 unread-badges.
- 8 новых JVM-тестов политики счётчика: типы чисел, границы, последний ID, legacy
  fallback, отсутствие видимого хвоста и арифметика нескольких тем. Вместе с ранее
  добавленными тестами сообщений — 22 теста.
- Проверка Kotlin-синтаксиса и git diff --check.
- APK не собран, UI/Android Keystore/поведение на телефоне не проверены: в этой среде
  нет Android SDK и Gradle. Нужна ручная проверка на двух устройствах.

## Ограничения

Изменение не восстанавливает задним числом отсутствующие серверные счётчики. Для
публичного официального канала используется фактический unreadCounts пользователя;
если сервер/публикация не создали его для пользователя вне participantIds, число
не выдумывается. Ранее накопленные сообщения в таком канале не пересчитываются
отдельной массовой загрузкой истории. Тесты проверяют существующий персональный
счётчик официального канала и права его сброса, а не серверную рассылку всем аккаунтам.

Проверить перед выпуском: два телефона, закрытый чат → 3 входящих → бейдж 3; открытие
и показ хвоста → исчезновение; ещё одно входящее → 1; выключенные подтверждения;
чтение старой истории; переход в фон; две темы группы с разным числом непрочитанных.
