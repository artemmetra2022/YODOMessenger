# Веб: инструменты объектов, горячие клавиши и уведомления

Изменения от 25 октября 2026. Дополняют предыдущие веб-доски и исправление совместимости веб → Android. Сайт не опубликован; рабочий Firebase не изменялся.

## 1. Доски

### Выделение и изменение объектов

- Инструмент **«Выделение» (V)**: нажмите объект; рамка показывает выделение.
- Перетаскивание выделенного объекта — перемещение. Сдвиг ограничивается целым объектом, чтобы он не искажался на краю листа.
- Маркер в правом нижнем углу рамки — изменение размера с сохранением пропорций. Доступны также кнопки «Уменьшить» / «Увеличить».
- Поле **«Угол»** — поворот в градусах. Углы нормализуются в диапазон [0, 360), объект целиком вписывается в лист; слишком большой объект не сохраняется.
- **«Копия»**, **«Удалить»**, изменение текста текстового объекта.
- Стрелки сдвигают объект на 1 точку, Shift + стрелки — на 10.
- Операции входят в существующую историю отмены/повтора.

Изменения совместимы с форматом Android CanvasCodec v4. Каждый изменённый объект получает новый UUID; в общей доске замена старого объекта новым выполняется существующей транзакцией с проверкой исходного объекта и поколения. Если участник уже изменил/удалил исходник, устаревшая правка отклоняется. Отмена не восстанавливает исходник, если результат замены уже удалён другим участником. Множественное выделение пока не добавлено.

### Масштаб и перемещение холста

- Кнопки − / +, «Вписать»: от 50% до 600% относительно вписанного листа.
- Ctrl/⌘ + колесо масштабирует у указателя.
- Инструмент **«Перемещение холста» (H)** — перетаскивание увеличенного листа.
- На сенсорном экране — масштаб двумя пальцами. Начало такого жеста отменяет незавершённый штрих, не добавляя случайный объект.
- В JSON/PNG и при отправке в чат сохраняется весь лист без рамки выделения и без экранного масштаба. Размер документа не меняется от зума.

Остальные существующие инструменты, локальное шифрованное сохранение и общая доска сохранены. Изображения/стикеры на холсте, типографские формулы, курсоры участников и полноценная серверная история изменений в это обновление не входят. Общая доска, как и раньше, без E2EE.

## 2. Горячие клавиши

В боковой панели есть кнопка **?**, в редакторе — **«Клавиши»**. Справка доступна также по F1, закрывается по Escape и имеет ограничение фокуса внутри диалога.

| Сочетание | Действие |
| --- | --- |
| Ctrl/⌘ + K | Быстрый поиск по названиям доступных чатов; Enter открывает первый результат |
| Alt + ↑ / ↓ | Предыдущий / следующий чат в порядке списка быстрого перехода |
| Ctrl/⌘ + Enter | Отправить сообщение |
| Ctrl/⌘ + , | Настройки |
| Ctrl/⌘ + Shift + B | Библиотека досок |
| Ctrl/⌘ + Shift + S | Общая доска текущего чата, если она доступна |
| Ctrl/⌘ + Shift + M | Отключить уведомления текущего чата без срока / вернуть |
| F1 | Справка |

В редакторе:

| Сочетание | Действие |
| --- | --- |
| V / H | Выделение / перемещение холста |
| B или P / E / T | Карандаш / ластик / текст |
| L / R / O | Линия / прямоугольник / эллипс |
| Ctrl/⌘ + Z | Отмена |
| Ctrl/⌘ + Shift + Z, Ctrl/⌘ + Y | Повтор |
| Delete (или Backspace вне поля) | Удаление выделенного объекта |
| Стрелки / Shift + стрелки | Перемещение на 1 / 10 точек |
| + / − / 0 | Приблизить / отдалить / вписать |
| Escape | Отменить незавершённый жест, снять выделение; следующий Escape закрывает редактор |

Буквенные команды определяются по `KeyboardEvent.code`, поэтому работают и при русской раскладке. В текстовых полях редактора не перехватываются обычный ввод и штатная отмена текста. Во время IME-композиции и AltGraph команды не выполняются. Глобальные команды не срабатывают поверх открытого диалога (кроме справки F1). Сочетания, зарезервированные ОС/браузером, могут не дойти до страницы — для действий остаются кнопки.

Поиск чатов не является полнотекстовым поиском переписки и не отправляет запрос на сторонний сервер.

## 3. Настройки уведомлений

**Настройки → Уведомления**:

- общий переключатель уведомлений в этом браузере;
- отдельная кнопка запроса разрешения браузера — автоматических запросов при входе больше нет;
- звук новых сообщений и тест звука/баннера;
- показ текста в баннерах (по умолчанию выключен);
- «Не беспокоить»: 1 час, 8 часов, 24 часа или до ручного включения.

**«Звук» / «Тихо» в заголовке чата**:

- не отключать;
- отключить на 1, 8 или 24 часа;
- отключить без срока.

Настройки сохраняются в localStorage отдельно для UID аккаунта и синхронизируются между вкладками через событие storage. Они не изменяют настройки Android и не синхронизируются между разными браузерами/устройствами. При запрете хранилища показано предупреждение: новые настройки работают только в памяти вкладки. После истечения срока уведомления разрешаются автоматически; интерфейс обновляется при взаимодействии/возвращении на страницу и периодически.

Новые сообщения отслеживаются по обновлениям чатов, а не только открытой переписки. Первоначальная загрузка истории не создаёт шквал баннеров. Одинаковый ID сообщения не уведомляет повторно в данной вкладке. Перед уведомлением читается соответствующее сообщение, когда доступен `lastMessageId`, чтобы учесть `silent`, удаление и срок жизни. Это дополнительное чтение Firestore на новое сообщение. Для старых клиентов без `lastMessageId` используется ограниченное превью метаданных, без гарантии проверки флага silent.

Не уведомляются: собственные сообщения, сообщения активного чата при видимой странице, заглушённые чаты, режим «Не беспокоить», тихие сообщения. Для PRIVATE и зашифрованных сообщений текст баннера всегда общий, даже если показ превью включён. Приватные ключи телефона не переносятся. Активные баннеры закрываются при смене аккаунта/выходе, старый баннер не открывает чат другого аккаунта.

### Ограничения браузера

- Уведомления работают только пока страница загружена. Service Worker, Web Push и доставка при закрытой странице НЕ добавлялись.
- Для баннеров нужно разрешение браузера. Отказ нельзя обойти настройкой сайта.
- Некоторые мобильные браузеры не поддерживают `new Notification` из обычной страницы, даже при наличии API; фоновые мобильные push потребуют отдельного этапа.
- Звук создаётся локально Web Audio без внешних файлов. После перезагрузки браузер может требовать взаимодействия со страницей для запуска аудио. Общий переключатель, заглушение и «Не беспокоить» действуют и на звук.
- Кнопка теста — явная проверка пользователем, поэтому может проиграть звук/показать тестовый баннер независимо от общего режима тишины.
- Дедупликация ведётся на вкладку; одинаковый tag заменяет баннер чата. Гарантия единственного звука при нескольких открытых вкладках пока не реализована.

## Проверки

Выполнено в среде разработки:

- 38 Node-тестов: предыдущие форматы/ограничения/лендинг + геометрия Android, неизменяемые замены, защита undo от восстановления удалённых объектов, маршрутизация клавиш, приватность превью, истечение mute/DND.
- Chromium: исходные сценарии редактора; выделение, перемещение, поворот v4, изменение размера, копирование/удаление, undo/redo с клавиатуры, zoom/pan, PNG без рамки и масштаба.
- Реальные сенсорные события в мобильном Chromium: масштабирование двумя пальцами, отмена предварительного штриха.
- Полный веб-интерфейс с подменённым SDK Firebase: защищённая отправка и все основные сочетания, уведомления неактивных чатов, отсутствие дублей, silent, DND, mute, безопасные превью, выход и закрытие баннеров, компоновка 390 px.
- Сохранение настроек после перезагрузки, разделение аккаунтов, запрещённое/отсутствующее API уведомлений, отказ localStorage, фокус и начальная прокрутка справки.
- Независимый тест WebCrypto → Python Tink предыдущего исправления сообщений — пройден повторно.
- Визуальная проверка редактора, справки, быстрого перехода и настроек на настольном/узком экранах.

Не выполнялись: деплой Hosting/правил, запись в рабочий Firebase, Firebase Emulator, сборка Android, физические телефоны и реальные системные баннеры/звук во всех целевых браузерах. Уведомления в интеграционном тесте подменены тестовым API; проверены решения о показе и содержание, а не доставляемость ОС.

### Повторить

```sh
node --test tests/web/*.test.mjs
node --check web/app.js
# С установленными Playwright и Chromium, при запущенном сервере корня проекта:
python -m http.server 8765 --directory .
# В другом терминале:
node tests/web/boards-ui.mjs
node tests/web/board-transforms-ui.mjs
node tests/web/preferences-ui.mjs
node tests/web/app-compat-ui.mjs
# Дополнительно, с установленным Python tink:
python tests/web/hpke-tink-interop.py
```

Браузерные тесты поддерживают `CHROMIUM_PATH` и `YODO_TEST_URL`. Стенды находятся вне `web/`, в Hosting не попадают.

## Перед публикацией

1. Заменить проект содержимым архива, сохранив прежние данные/ключи пользователей. Схема Firebase и Android не менялись.
2. На тестовом Firebase с актуальными правилами проверить общую доску веб ↔ Android: перемещение/поворот, конкурирующие правки, undo, очистку и потерю сети.
3. Проверить реальные разрешения, звук и баннеры целевых браузеров: разрешено/запрещено, скрытая вкладка, неактивный чат, DND, таймер mute, несколько вкладок и выход из аккаунта.
4. Проверить сочетания на Windows/Linux/macOS и русской раскладке; ОС может резервировать часть команд.
5. После приёмки опубликовать обычным процессом Firebase Hosting. Новые Firebase-права, приватные ключи, внешние аудиосервисы или отключение защитных правил не требуются.
