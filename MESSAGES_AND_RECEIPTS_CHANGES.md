# Последовательная отправка сообщений и точные подтверждения

## Исправления

- Текст сохраняется в локальную очередь до очистки поля ввода. Ожидание сети больше
  не блокирует написание следующего сообщения. Очередь сериализуется отдельно для
  каждого чата; лимит восемь сообщений за десять секунд выдерживается ожиданием,
  а не отбрасыванием текста. В очереди может быть до 200 текстовых сообщений.
- Очередь хранится атомарно, зашифрована AES-GCM ключом Android Keystore и разделена
  по аккаунтам. Файлы находятся в noBackupFilesDir. Выход из чата не отменяет отправку.
  После перезапуска она возобновляется при создании ChatViewModel / открытии чата.
  Смена аккаунта отменяет старые обработчики и не отправляет их текст от нового UID.
- У каждого запроса постоянный ID. Повторная транзакция не создаёт второй документ
  сообщения и не увеличивает счётчик непрочитанных повторно, если документ уже существует.
- Ошибка видна в ленте и на панели «Повторить». Ошибка первого запроса приостанавливает
  последующие в том же чате, сохраняя их порядок и содержимое; другие чаты независимы.
  Постоянные ошибки шифрования/доступа требуют сначала устранить причину.
  «Убрать» с подтверждением удаляет только сообщения с ошибкой и освобождает очередь.
- Локальная и серверная версии одного сообщения объединяются по ID. Локальное эхо
  сохраняется между завершением отправки и приходом снимка, чтобы пузырь не исчезал.
- Прокрутка считает также разделители дат, не теряет последние сообщения и не должна
  уводить от чтения истории при новых входящих. Собственная новая отправка прокручивает вниз.
- Вложения и редактирование по-прежнему отправляются прежним способом, не через
  текстовую очередь. Их занятое состояние теперь снимается в finally, включая ошибки
  и ранний выход при ограничении поддержки. Параллельный запуск вложений блокируется.

## Подтверждения и оформление

- Одна компактная система в текстовых/медиа-пузырях и списке чатов: часы для отправки,
  одна галочка «Отправлено», двойная «Доставлено», синяя двойная «Прочитано», ошибка.
  Внутри чата есть небольшая подпись на лёгкой подложке; доступность не зависит от цвета.
- Подписка сообщений включает изменения метаданных Firestore, поэтому подтверждение
  сервера обновляет UI даже без изменения содержимого. Изменение реакции/подтверждения
  больше не возвращает уже доставленное сообщение к состоянию отправки.
- Доставка отмечается только по серверному снимку, не по кэшу и не по «в сети».
  Если у получателя нет активной подписки сообщений, она может появиться только при
  открытии чата. Push сам по себе не используется как доказательство доставки:
  гарантированный ID сообщения в существующем push-протоколе не подтверждён.
- Чтение отмечается для видимых сообщений в RESUMED-окне после 350 мс показа, с
  повтором при временных ошибках. Свёрнутый/неактивный чат не помечает всё прочитанным.
  Учитывается настройка приватности подтверждений. Явная кнопка «Прочитано» в
  уведомлении по-прежнему намеренно отмечает весь чат.
- Для новых сообщений сохраняется снимок получателей и персональные deliveredTo/readBy.
  В группе окончательные «Доставлено»/«Прочитано» означают всех получателей; промежуточное
  чтение показывает «Прочитали N/M». Состав получателей фиксируется при отправке.
- Транзакции сохраняют чужие подтверждения, не понижают READ и обновляют статус превью
  только при совпадении точного lastMessageId. Бейдж сбрасывается только если текущий
  последний ID действительно входит в прочитанную/показанную выборку.
- У старых сообщений персональных данных нет: сохраняется совместимость со скалярным
  статусом, без выдумывания числа прочитавших задним числом.
- Правила запрещают получателю подтверждать другого участника и автору подделывать
  обновление подтверждения. Зафиксированы recipientIds/sentAt; изменения статуса не
  могут одновременно менять текст. Малые транзакции и ограниченный повтор разрешают
  конфликты одновременного чтения без ослабления правил.

## Установка и совместимость

1. Сначала развернуть приложенные правила: `firebase deploy --only firestore:rules`.
2. Собрать APK по существующему CI/workflow проекта (JDK 17, Gradle 8.7, Android SDK 34,
   собственный google-services.json и прежний ключ подписи обновлений).
3. Обновить приложения участников для новых персональных подтверждений. Старые клиенты
   смогут получать сообщения, но их скалярные подтверждения для новых документов могут
   отклоняться правилами; на время смешанных версий индикаторы могут не продвигаться.

Изменения не отправлены в GitHub и не развёрнуты в рабочей базе.

## Проверки и ограничения

- Локальный Firestore Emulator: 153 теста (34 checklist, 42 private-text-security,
  20 canvas, 31 shared-board, 26 message-receipts). Новые проверки: серии отправок,
  идемпотентный повтор, одновременные читатели, транзакция восьми подтверждений,
  отсутствие отката READ/подмены получателя и сброс бейджа без потери нового входящего.
- Kotlin 2.2.20 + JUnit: 14 тестов resolver/объединения очереди/индекса прокрутки.
  Дополнительно ранее проверены 7 тестов прогресса загрузки и политики интервала доски.
- Синтаксическая проверка изменённых Kotlin-файлов, `git diff --check`, `node --check web/admin.js`.
- Полная Android-сборка, работа Android Keystore/очереди на устройстве, Compose UI
  и instrumentation-тесты здесь НЕ проверены: SDK/Gradle/Android-эмулятора нет.

Перед выпуском проверить на двух телефонах: 10–15 быстрых текстов; потерю сети и
«Повторить»; закрытие/перезапуск с очередью; смену аккаунта; сообщения с ответом и TTL;
фото после ошибки; открытый и свёрнутый чат; выключенные подтверждения; группу с
тремя участниками и одновременным чтением; длинную историю с несколькими датами.
