# Этап 5 — совместное рисование онлайн (на любом расстоянии)

Изменения исходников от 15.10.2026. Android-сборка, Gradle-тесты, деплой правил и проверка на
двух телефонах **не выполнялись** (в среде не было Kotlin/Gradle/Firebase). Код написан по
образцу существующего Nearby-транспорта и проверен только чтением и чисто-логическими тестами
(`CanvasOnlineSupportTest`, не запускались).

## Как пользоваться

1. Ведущий: «Рисовать вместе · онлайн» → «Создать приглашение». Появляется код вида `ABCD-EFGH`
   и кнопка «Поделиться кодом». Код одноразовый и действует 10 минут.
2. Участник: «Рисовать вместе · онлайн» → «Ввести код» → «Присоединиться».
3. Ведущий видит «Пустить «Имя»?» и разрешает или отклоняет вход.
4. Ведущий передаёт текущую доску вместе с фоном, дальше рисуют вдвоём. Как и в Nearby:
   ведущий — арбитр порядка правок, у каждого свой «Отмена/Повтор», курсор собеседника виден.
5. «Отключиться» завершает сессию у обоих.

Рядом-режим (Nearby) остался без изменений; одновременно работает только один из режимов.

## Как устроено

Тот же протокол доски (v4: снимок, предложение, подтверждение, курсор) — меняется только канал.
`CanvasOnlineTransport` реализует `CanvasTransport` поверх Firestore; `CanvasCollabHub`
объединяет две независимые сессии (Nearby и онлайн) под одним состоянием для экрана.

Коллекции Firestore:

| Путь | Назначение |
|---|---|
| `canvasInvites/{КОД}` | код → id сессии, живёт 10 минут, удаляется при входе/завершении |
| `canvasSessions/{id}` | участники, `status`: open → joined → active → ended, «пульс» обоих |
| `canvasSessions/{id}/toGuest/{0000000001…}` | пакеты ведущего → участнику |
| `canvasSessions/{id}/toHost/{…}` | пакеты участника → ведущему |
| `canvasSessions/{id}/cursors/{uid}` | последний курсор участника |

- Пакеты — кадры `CanvasFrames` по ≤24 КБ в base64, создаются один раз и не меняются; номера
  с нулями слева дают порядок. Получатель складывает пакеты по порядку (`CanvasPacketReorder`),
  дубликаты игнорирует, «дыра» дольше 20 с завершает сессию.
- Запись пакетов — группами не более 15 (лимит обращений `get()` в правилах Firestore).
- «Пульс»: каждый участник раз в 20 с обновляет свою метку; нет изменений 75 с — сессия
  завершается. Курсор пишется не чаще раза в 350 мс.
- Время ожидания входа — 3 минуты (в Nearby — 30 с): ведущему нужно время, чтобы разрешить.
- При завершении: статус `ended`, пакеты удаляются, ведущий удаляет приглашение и сессию.

## Безопасность и ограничения (важно)

- **Содержимое доски идёт через сервер без сквозного шифрования**: рисунок и фон видят участники и
  владелец проекта Firebase. Это прямо написано в диалоге перед созданием приглашения.
- Доступ к сессии — только по неугадываемому id и только двум участникам (правила Firestore);
  вход — по одноразовому коду и после разрешения ведущего. Имя участника вводит он сам, оно не
  проверяется; ведущий должен пускать только того, кому передал код.
- Код ~40 бит: подбор онлайн неэффективен из-за срока 10 минут и одного места, но отдельного
  ограничения числа попыток на сервере нет.
- Приложение должно оставаться открытым у обоих. В фоне Android может приостановить связь —
  сессия завершится по «пульсу». Переподключения к той же сессии нет: нужна новая.
- Задержка правки — около 0,3–1,5 с (путь через сервер и ведущего); при плохой сети больше.
- **Стоимость Firebase**: каждая правка — запись и чтение пакетов, курсор — до 3 записей/с на
  участника, «пульс» — 3 записи/мин. Большой фон передаётся десятками пакетов. Для оценки
  расходов проверьте квоты проекта.
- Доска из совместной сессии у участника заменяет текущую (его прежняя сохраняется локально).

## Что нужно сделать перед включением

1. **Развернуть `firestore.rules`** (иначе онлайн-режим отвечает «Нет доступа…»).
2. Включить TTL-политику Firestore по полю `expireAt` для групп коллекций `canvasSessions`,
   `canvasInvites`, `toGuest`, `toHost`, `cursors` — подчистит остатки, если приложение закрыли
   без завершения сессии.
3. Собрать приложение, прогнать JVM-тесты (`CanvasOnlineSupportTest` и существующие).
4. Проверить на двух телефонах в разных сетях (Wi-Fi и мобильный интернет): вход по коду,
   отклонение входа, истёкший и повторно использованный код, рисование вдвоём, фон, формулы,
   новые фигуры, «Отмена/Повтор», обрыв связи, закрытие приложения у одного из участников.
5. Убедиться, что в консоли Firebase после завершения сессии не остаются пакеты.

## Не реализовано

Больше двух участников, переподключение к той же сессии, сквозное шифрование, приглашение
прямо из чата (сейчас код передаётся любым мессенджером), проверка имени участника через профиль.
