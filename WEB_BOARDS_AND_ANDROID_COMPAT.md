# Доски в веб-клиенте и совместимость сообщений с Android

## Что добавлено

- Кнопка **«Доски»** в боковой панели: создание, библиотека и удаление личных досок.
- Рисование мышью, пером и касанием: карандаш, полупрозрачный маркер, линия, стрелка, прямоугольник, скруглённый прямоугольник, круг, эллипс, треугольник, ромб, текст, объектный ластик.
- Цвет, толщина, сетка (клетка / точки / без сетки), отмена и повтор до 60 действий.
- Личные доски автоматически сохраняются в IndexedDB. Данные зашифрованы AES-GCM, ключ браузера неэкспортируемый, аккаунты разделены. Это НЕ защита от XSS, вредоносного расширения или компрометации браузера. Очистка данных сайта удаляет и ключ, и библиотеку. Рекомендуются JSON-копии.
- Экспорт PNG и редактируемого JSON `yodo.canvas`, импорт JSON, отправка рисунка в чат как обычного изображения (JPEG для ограничения размера документа Firestore).
- **Общая доска чата**: кнопка «Доска» в заголовке личного чата или группы, живая карточка, редактор с синхронизацией. Все участники могут рисовать и удалять объекты. Каналы, поддержка и Избранное исключены, как в Android.

## Совместимость досок

Общая доска использует СУЩЕСТВУЮЩИЕ пути Android:

- `chats/{chatId}/sharedBoard/meta`
- `chats/{chatId}/sharedBoardObjects/{objectId}`

Поля `json`, `authorUid`, `at`, `generation` совпадают с `SharedBoardRepository`. Один объект — один неизменяемый документ; JSON — обёртка CanvasSharedCodec с нулевым UUID, листом 1200×900 и одним объектом. Типы объектов, signed ARGB и версии формата 1/3/4 совпадают с CanvasCodec. Учитываются `generation`, `deleted`, `clearing`. Транзакции не дают устаревшему редактору воскресить очищенную/удалённую доску; отмена не перезаписывает всю доску и не удаляет рисунки других участников. Пересоздание tombstone — только по явному подтверждению.

Лимиты клиента: 300 объектов, 2048 точек в линии, 60000 точек всего; проверка импортируемого JSON (5 МБ, глубина 24, координаты, UUID и типы). Для общей доски применён предел JSON одного объекта 120000 символов. Как и в Android, лимит 300 объектов не является глобальной серверной квотой: одновременные добавления разных участников могут его превысить; веб показывает до 300 объектов текущего поколения. Подписка читает коллекцию объектов целиком; учитывайте чтения Firestore в больших группах.

**Содержимое общей доски не имеет сквозного шифрования.** Оно доступно участникам и серверу Firebase. Предупреждение показано при создании и в редакторе.

Личные доски не синхронизируются между браузером и телефоном автоматически. Для переноса используйте JSON, для общего рисования — общую доску чата.

Это не полный перенос Android-редактора: нет создания/типографского рендеринга формул, распознавания фигур и Nearby/онлайн-сессий по коду. Выделение, трансформации объектов и масштабирование добавлены следующим обновлением — см. WEB_BOARD_TOOLS_SHORTCUTS_NOTIFICATIONS.md. Импортированные формулы сохраняются и отображаются текстом исходного выражения; математический синтаксис проверяет Android при импорте. Не обещается полное визуальное совпадение переносов текста, поворотов и шаблонов с Android.

## Исправление веб → Android

В исходной версии веб-клиент не создавал личные защищённые конверты Android и блокировал отправку в обычный PRIVATE-чат. Старый открытый формат не совместим с текущими защитными правилами. Новая отправка использует:

- опубликованные `users/{uid}.publicKey` обоих участников;
- Tink HPKE: X25519 / HKDF-SHA256 / AES-256-GCM, контекст `yodo-e2e-v1`;
- `encrypted: true`, `encryptedPayloadVersion: 2`, `encByUid` для обоих UID;
- JSON `{text, replyText?, replySenderName?}` внутри шифртекста;
- пустой серверный `text`, без открытых цитат и `lastMessagePlain`;
- правильные `replyToMessageId` и поля пересылки Android;
- `sentAt`, `recipientIds`, `deliveredTo`, `readBy`, `lastMessageId` для актуальных подтверждений доставки/прочтения.

Используются криптографические примитивы WebCrypto и реализация формата RFC 9180 в `private-send.mjs`. Проверена независимой библиотекой Python Tink на том же шаблоне ключей, что у Android, включая TINK/RAW, оба получателя, v2 payload, отпечатки и отказ при порче шифртекста/контекста. Это тест совместимости, НЕ независимый аудит безопасности.

Один путь отправки применяется к тексту, подписям, цитатам, пересылкам, фото/рисункам и голосовым. Для медиа без текстовых полей ключ не требуется: сами медиа остаются без E2EE, как в Android. Группы/каналы/поддержка сохраняют свою существующую модель защиты. Смена ключа останавливает текстовую отправку до явной сверки через кнопку **«Ключи»**. Отпечаток SHA-256 соответствует BinaryKeysetWriter Android. Первое получение ключа — TOFU, а не подтверждение личности. Решения доверия хранятся отдельно для аккаунта в данном браузере.

Не создаются и не заменяются ключи телефона. Нет отката к открытому личному тексту при ошибке. Текст, вложение и цитата формы остаются до успешного коммита. Изображения и голосовые не становятся сквозным шифрованием от наличия текстового конверта.

**Веб-клиент остаётся send-only для защищённого текста**: приватный ключ телефона не переносится. Он не расшифровывает защищённую историю и входящие сообщения; собственный отправленный текст показан из памяти вкладки и исчезает после перезагрузки/выхода. Это прямо указано над полем ввода. Старые сообщения с потерянными/заменёнными ключами автоматически не восстанавливаются. Для отправки текста оба участника должны заранее открыть актуальный Android-клиент и опубликовать ключи. Браузеру нужны HTTPS/localhost и поддержка WebCrypto X25519.

Непрочитанный браузером защищённый текст не помечается как READ. Для прочитанного открытого текста обновляются собственные receipt-массивы и агрегированный статус транзакцией.

## Проверки

Выполнено:

- `node --check web/app.js` и проверка синтаксиса всех новых модулей;
- `node --test tests/web/*.test.mjs` — 38 пройденных тестов (включая последующую доработку), включая старые тесты лендинга;
- Python Tink interoperability — успешная расшифровка веб-конвертов для обоих телефонов, TINK/RAW, совпадение отпечатков, отказ при неверном контексте и изменении шифртекста;
- Chromium: рисование, текст, ластик, сетка, отмена/повтор при одновременном рисунке другого участника, экспорт, отправка изображения, generation fence, tombstone, сохранение и повторное открытие, изоляция аккаунтов;
- полный веб-клиент с подменённым SDK Firebase: загрузка, отправка v2, приватное превью, создание общей доски, выход и очистка;
- визуальная проверка редактора, библиотеки и состояния ошибки на настольном и узком (390 px) экранах.

Не выполнялось: деплой сайта/правил, запись в рабочий Firebase, Firebase Emulator, сборка APK и проверка на физических телефонах. Автотесты синхронизации используют тестовый адаптер, а не настоящий сервер. Успешный криптографический тест не заменяет проверку веб ↔ конкретный APK на тестовом Firebase.

### Повторить тесты

Из корня проекта:

```sh
node --test tests/web/*.test.mjs
node --check web/app.js
```

Независимый криптотест (только синтетические временные ключи):

```sh
python -m pip install tink
python tests/web/hpke-tink-interop.py
```

Браузерные тесты требуют Node, Playwright и Chromium; эти зависимости НЕ нужны посетителям сайта:

```sh
npm install --no-save playwright
python -m http.server 8765 --directory .
# В другом терминале:
node tests/web/boards-ui.mjs
node tests/web/board-transforms-ui.mjs
node tests/web/preferences-ui.mjs
node tests/web/app-compat-ui.mjs
```

Можно задать `CHROMIUM_PATH` и `YODO_TEST_URL`. В `fixtures/synthetic-hpke-public.json` находятся только сгенерированные тестовые ПУБЛИЧНЫЕ ключи, не ключи пользователей. HTML-стенды находятся вне `web/` и не публикуются Hosting.

## Установка и обязательная приёмка

1. Заменить файлы проекта содержимым архива. Код Android и `firestore.rules` не менялись.
2. На ТЕСТОВОМ Firebase убедиться, что уже развёрнуты правила из приложенного `firestore.rules`, в том числе `sharedBoard`, `sharedBoardObjects`, поколения/tombstone и защищённые сообщения v2. Не ослаблять защитные правила ради старых клиентов.
3. Войти в два актуальных Android-клиента, открыть личный чат для публикации ключей, затем войти в веб.
4. Отправить из веба русский текст/эмодзи, фото с подписью, ответ с цитатой, пересылку и голосовое; проверить на телефонах отправителя и получателя. Проверить отказ при отсутствии/смене ключа и сохранность текста формы.
5. Создать общую доску из веба и из Android; проверить рисунки в обе стороны, ластик, отмену, сетку, группу, очистку/удаление из Android при открытом веб-редакторе, потерю сети и выход участника из чата.
6. Проверить браузеры целевой аудитории (в частности X25519), лимиты Firebase и IndexedDB. Транзакции общей доски требуют сети: при её отсутствии отображается ошибка, штрих не считается сохранённым; локальные доски не требуют сети после загрузки приложения.
7. После приёмки опубликовать обычным процессом Firebase Hosting. Публикация не выполнялась этим изменением.
